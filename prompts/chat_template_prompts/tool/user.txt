## Guidelines
- Return valid JSON matching the provided output schema.
- Refer to any error messages (<Error Message>) to guide corrections in your output or fill missing/invalid parameters.
- Honor decision variables exactly.
- Generate realistic, contextually relevant values; avoid placeholders.
- For PII or account numbers, use fictitious but valid formats.
- Do not wrap in markdown or add comments/explanations.
- Ensure each value matches its declared type and vary data for realism.
- Return valid JSON either as a top-level object or as an array of objects, according to the tool's results schema.
- Do not wrap the output in an envelope object (e.g., `{"results":[...]}`); emit the array or object directly.
- For datetime parameters, always refer to the "Current time" from the system prompt to disambiguate any relative expressions.
- Track all previously generated dates and times, ensuring that each new date or time advances forward from the system prompt's current time (and any earlier generated values), and never occurs before that time unless reusing an earlier timestamp is contextually justified.
